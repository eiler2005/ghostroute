# Эксплуатация GhostRoute Guard

Для повседневной работы: [руководство пользователя](user-guide.md).
Для разработки и выпуска: [проверки и приёмка](../tests/README.md).

## Локальные компоненты

| Компонент | Где находится | Назначение |
|---|---|---|
| Исходники | `modules/mac-privacy-guard/` | Python gate/controller, SwiftUI package, Chrome integration, installer, тесты |
| Приложение | `~/Applications/GhostRoute Guard.app` | Собранный ad-hoc signed bundle; не App Store/notarized distribution |
| Состояние | `~/Library/Application Support/GhostRoute Guard/` | Приватный каталог 700 |
| Профиль | `profile.json` внутри состояния | Маршруты, доверенные сертификаты/выходы, credentials; 600 |
| `Browser/` | Внутри состояния | Отдельные Chrome cookies, история и настройки |
| `gate-port`, `browser-pid`, `app.lock` | Внутри состояния | Локальное владение listener/browser; не deployment inventory |
| `Chrome Blocker/` | Внутри состояния | Unpacked MV3 extension; включается отдельно в Chrome |
| `Chrome Native Host/` | Внутри состояния | Приватный stdio → Unix socket bridge; события и фиксированные команды Chrome, без управления маршрутом |
| `chrome-events.sock` | Внутри состояния | Локальный сокет 600; создаётся приложением, удаляется при штатном выходе |
| Native host manifest | `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/org.ghostroute.guard.events.json` | Разрешает связь только ID данного unpacked extension |
| Тестовые отчёты | Игнорируемый `reports/mac-guard-design/` | Локальные доказательства, скриншоты и приватная подготовка |

Bundle содержит копию исходников, но использует зафиксированный путь к Python,
который его собирал. После удаления/замены этого interpreter пересобрать bundle.
Это не копия роутера/VPS и не отдельная инфраструктура egress.

Swift Package состоит из `GuardCore` (модели и клиент локального API), `GuardUI`
(MainActor store и нативные представления), `GuardApp` (процесс и окно AppKit).
HTML/WKWebView не используется. Локальный HTTP endpoint служит только API с
токеном; его корень возвращает 404, панели в браузере нет.

Справка встроена в боковую панель и меню «Справка» macOS. Раздел **Google Chrome**
управляет подключёнными агентами: открыть/закрыть доступ, передача событий,
подготовленная HTTP-диагностика, очистка и запрос выбранного текста. Основные кнопки
доступны также на экране «Обзор». [Авто GhostRoute](strict-mode.md) использует
обязательный PAC/gate sensitive-каталога, qualification и явное владение
proxy/privacy. Optional browser независим. См. [контракт агента](chrome-agent.md).
В расширении есть popup со статусом, отдельная справка и панель DevTools Guard.

Проверки нативного клиента и состояния, доступные с Command Line Tools без Xcode:

```bash
swift run --package-path modules/mac-privacy-guard/native GuardNativeChecks
```

Для проверки без создания локального `.build` используйте
`--scratch-path reports/mac-guard-ui/swift-build` перед именем `GuardNativeChecks`.

## Приватный профиль

Формат ниже — **шаблон с placeholders**, не готовый профиль. Подставлять значения
только в приватном файле. Корневые поля и route fields проверяются строго;
неизвестные типы, fallback/direct fields и пустые allowlists для HTTPS запрещены.

```json
{
  "schema_version": 1,
  "sensitive_domains": ["sensitive.example.org"],
  "routes": [{
    "id": "home_sensitive",
    "kind": "https_proxy",
    "host": "<home_ingress_host>",
    "port": "<numeric_https_ingress_port>",
    "server_name": "<certificate_hostname>",
    "username": "<existing_selected_client>",
    "password": "<private_credential>",
    "certificate_sha256": "<independently_obtained_leaf_certificate_sha256>",
    "allowed_domains": ["sensitive.example.org"],
    "probe_url": "https://sensitive.example.org/cdn-cgi/trace",
    "probe_format": "cloudflare_trace",
    "approved_exit_ips": ["<approved_public_exit_ip>"]
  }]
}
```

1. Использовать уже существующий C **HTTPS CONNECT** URI и соответствующую
   выбранную identity. Не брать Naive URI/порт, не менять публичный ingress и
   не регенерировать другие клиентские импорты. Повторное использование identity
   объединяет её server-side accounting; отдельная новая identity — отдельный
   согласованный deploy.
2. Получить leaf certificate по уже доверенному SSH/control пути либо использовать
   публично доверенный сертификат с верным именем (тогда поле pin опустить).
   Нельзя получить «доверенный» pin с того же непроверенного первого соединения.
3. Проверить deployed sensitive rule, его inbound scope и отсутствие direct
   catch-all раньше него. Все `allowed_domains` должны быть покрыты этой policy.
   Базовый список — `configs/sensitive-domains.txt`; он содержит нужные auth-домены,
   но не все возможные ресурсы любой страницы.
4. Получить ожидаемый публичный egress IP из доверенного управления backend.
   Не копировать автоматически IP текущего Mac и не одобрять наблюдаемый выход
   только потому, что запрос успешен. Backend server IP и egress IP могут
   различаться: при NAT нужна независимая проверка ожидаемого выхода.
5. Выбрать HTTPS canary, который сам попадает в эту же policy. `plain_ip` ожидает
   только IP в body; `cloudflare_trace` — ровно одну строку `ip=...`. Ответы с
   redirect, ошибкой, несколькими IP или неверным IP не открывают доступ.
6. Сохранить JSON с правами 600 и импортировать через приложение. Импорт закрывает
   старые соединения и требует повторной проверки. В Git профиль не помещать.

Exact certificate pin осознанно заменяет CA/hostname trust: доверяется конкретный
leaf DER, включая self-signed. Автоматического TOFU или обновления pin нет.
После штатного renew доступ закроется; сверить новый сертификат доверенным путём,
обновить приватный профиль и повторить проверку. Не удалять pin ради обхода ошибки.

## Одновременно с proxy-расширением Chrome

Guard сохраняет текущий совместимый inline PAC внешнего расширения и проверяет
sensitive-каталог раньше его правил. Остальные сайты продолжают использовать
сохранённые правила и авторизацию провайдера; его расширение остаётся включённым.
Эффективная PAC принадлежит Guard. Popup и приложение показывают наличие внешнего
снимка. Смена страны/сервера не синхронизируется автоматически; новый снимок и
ограничения remote PAC/fixed proxy описаны в [строгом режиме](strict-mode.md).
Исходный PAC остаётся только в настройках Chrome: не копировать его в отчёты,
логи, Git или обычный backup. Отключение Guard снимает его слой настроек Chrome
и возвращает нижележащую конфигурацию провайдера; sensitive-защита при этом снята.

## Сторонний VPN

Второй route может иметь поля:

```json
{
  "id": "approved_vpn",
  "kind": "bound_vpn",
  "interface": "utun9",
  "allowed_domains": [],
  "probe_url": "https://api.ipify.org/",
  "probe_format": "plain_ip",
  "approved_exit_ips": ["<approved_public_exit_ip>"]
}
```

`utun9` — вымышленный пример. Выбирать фактически принадлежащий конкретному VPN
интерфейс, а не первый интерфейс с этим префиксом. Сначала включить и независимо
квалифицировать VPN по [матрице](security-and-testing.md). Guard не запускает VPN,
не меняет маршруты macOS и не разрешает доступ через обычную physical interface.
При смене имени/index или IP выхода требуется проверка/обновление профиля.

Пустой VPN allowlist разрешает публичные HTTPS назначения через выбранный
туннель. DNS A lookup выполняется через DoH с фиксированным публичным bootstrap
в том же `utun`; system DNS для целевых сайтов не используется. IPv6 literals
получают IPv6 socket с binding; доменные AAAA в этой версии не запрашиваются.
Это ограничение совместимости, а не direct IPv6 fallback.

## Отказы и восстановление

В главном окне и popup **«Возобновить авто»** разрешает автоматическую проверку
выбранного агента. Только после подтверждения маршрута, каталога и ownership
Chrome получает доступ через strict gate. **«Закрыть доступ»** приостанавливает
авто и разрывает tracked strict tunnels. Нужен приватный профиль, DevTools не нужен.
Оба интерфейса управляют одним состоянием; ранее заблокированную страницу обновить.
Без engine или qualification каталог закрыт; owned PAC остаётся на закрытом gate.

В сворачиваемом разделе дополнительного браузера маршрут выбирается отдельно.
«Проверить маршрут» квалифицирует шлюз; «Закрыть шлюз» отменяет проверку и закрывает
туннели. **«Открыть в Guard»** запускает отдельный Chrome с fixed proxy. Состояние
этого шлюза не меняет блокировку обычного Chrome. Если переключение окна
недоступно, приложение предлагает выбрать отдельное окно вручную.

Журнал хранит последние 300 событий в памяти, включая закрытые соединения,
отказы, сетевые ошибки и управление доступом. Фильтры, поиск и детали объясняют
причину и источник. Счётчик «Заблокировано» показывает блокировки всех источников,
сбрасывая прежний поиск. «Показать все события» снимает все фильтры; подпись
«Показано … из …» отличает пустой журнал от скрытых событий. В деталях блокировки
Chrome можно открыть HTTPS-домен в защищённом браузере после проверки маршрута;
путь исходной страницы не сохраняется и не восстанавливается.
«Очистить» удаляет события, но сохраняет счётчики текущего
запуска. Отправленные/полученные байты учитывают данные внутри туннелей, включая
внутренний TLS; это не размер HTTP-страниц и не общий расход сети Mac.

Ошибки запуска и потери связи остаются в нативном журнале даже при недоступном
Python engine. «Повторить запуск» перезапускает только принадлежащий приложению
backend и сохраняет профиль. Нативная оболочка различает занятое владение,
недоступный порт и ошибку канала Chrome; неизвестные ошибки не раскрывают raw
exception/окружение. Повторное открытие приложения активирует уже запущенное окно.
Listener допускает повторную привязку после завершения прежнего экземпляра,
но не совместное владение портом двумя активными процессами.

Журнал отдельно отмечает передачу сайта защищённому Chrome и отказ запуска.
Первое событие означает успешную команду запуска, **не загрузку страницы**:
реальный трафик подтверждают разрешённые туннели/байты и проверка страницы.
URL проверяется на активный маршрут и каталог ещё до запуска браузера.

В общий журнал блокировщик передаёт через Native Messaging собственные срабатывания
правил deny и session allow. Главные счётчики приложения считают доставленные
запросы каталога за запуск, popup — локальные за сеанс worker; число на иконке
равно сумме разрешений и блокировок. Это не TCP-соединения и не HTTP-успех.
Обычные сайты вне каталога не записываются. Для разрешённого запроса байты и
длительность неизвестны; для медленной загрузки использовать HTTP-диагностику.
Сообщения не содержат URL-путь, query, tab ID, initiator и заголовки.
HTTP-метаданные и solicited response preview хранятся отдельно по
[контракту агента](chrome-agent.md); текст не попадает в журнал. Локальный канал
не имеет API открытия маршрута. «На связи» в настройках означает
свежий агент (до 6 секунд) хотя бы одного экземпляра, независимо от allow/block.
Без Guard блокировка работает, но события теряются; дискового буфера нет.
ID unpacked extension привязан к абсолютному пути. При переносе папки заново
выполнить installer для регистрации нового `allowed_origins`.

| Симптом | Безопасное действие |
|---|---|
| Проверка выхода не прошла | Проверить доступность и trust выбранного маршрута; не добавлять текущий IP вслепую |
| Не загружается ресурс страницы | Найти зависимость в DevTools локально; проверить её server-side policy перед добавлением в allowlist |
| Сертификат обновился | Сверить новый pin независимым доверенным способом |
| Старый защищённый Chrome остался после аварии | Закрыть именно его окно; обычный Chrome не завершать |
| «Шлюз недоступен», маршрутов нет | Прочитать ошибку внизу окна/журнале и нажать «Повторить запуск»; отсутствие списка не означает удаления профиля |
| Loopback gate port занят | Закрыть Guard и старый защищённый Chrome; определить владельца. Только после этого удалить `gate-port` и перезапустить |
| Счётчик блокировок растёт, таблица пуста | Нажать счётчик «Заблокировано» или «Показать все события» |
| Команда Chrome не подтверждена | Проверить выбранный сеанс и включение расширения; для HTTP открыть DevTools → Guard и разрешить управление |
| Нужно открыть sensitive в обычном Chrome | «Возобновить авто», дождаться защищённого статуса и обновить вкладку; при конфликте согласовать одного владельца proxy |
| Доступ в Chrome открыт, но страница всё ещё `ERR_BLOCKED_BY_CLIENT` | Обновить вкладку; проверить выбранный сеанс, версию/reload расширения и другие блокировщики. Проверка дополнительного шлюза не открывает обычный Chrome |
| Изменился VPN/сеть или Mac проснулся | Закрыть доступ и повторить проверку. Не считать предыдущий зелёный статус приёмкой нового подключения |
| Обычный Chrome открывает sensitive-сайт | Проверить включение blocker в этом профиле и Incognito; приложение не устанавливает его молча |

Strict lanes имеют отдельную проверку примерно раз в пять секунд, expiry десять
секунд и отдельные счётчики; подробности в [строгом режиме](strict-mode.md).
Optional-browser Guard разрывает tracked tunnels по Lock, смене профиля/маршрута и неудачной
периодической проверке. Проверка выполняется каждые 15 секунд; новый CONNECT
не принимается при возрасте успешной проверки более 45 секунд. VPN дополнительно
проверяется перед каждым CONNECT, затем каждый сокет проверяет index и binding.
Это не мгновенный детектор любого изменения server-side policy или DNS.
Существующий HTTPS tunnel к home proxy остаётся TLS-соединением с тем же peer.

Повторный launch всегда locked. При обычном выходе native shell завершает backend;
backend также замечает исчезновение parent process и закрывается. При убийстве
самого gate оставшийся Chrome сохраняет fixed proxy и теряет доступ. Не запускать
сохранённый профиль вручную без обязательных flags.

## Обновление, копия и rollback

1. Закрыть Guard и его браузер. Сохранить приватный `profile.json` в уже принятом
   **зашифрованном** recovery bundle. Профиль содержит пароль proxy.
2. Записать commit исходников. Переименовать прежний `.app` в локальный rollback
   bundle и выполнить `bin/install-mac` заново. Installer не перезаписывает
   существующее приложение и не трогает приватный профиль.
3. При обновлении sensitive-каталога пересобрать extension через
   `bin/install-mac --extension-only`, затем нажать Reload в `chrome://extensions`.
   Installer обновляет и Native Messaging host. Chrome может запросить принятие
   добавленных разрешений. «Показать папку расширения» в настройках открывает
   ровно установленную папку в Finder. Для изолированной сборки укажите
   `--native-hosts <private_build_dir>` вместе с временными `--app`/`--extension`.
   Guard allowlist обновляется отдельно после сверки deployed router policy.
4. Для rollback закрыть новый экземпляр, вернуть прежний bundle и соответствующий
   приватный профиль; проверить маршрут до открытия сайтов.

`Browser/` содержит сессии/историю и по умолчанию не должен попадать в обычный
диагностический архив. Для восстановления маршрутов достаточно исходников,
Python/Chrome и приватного профиля; browser sessions можно создать заново.
`gate-port`, lock, Unix socket и PID не переносить на другой Mac. Blocker пересобрать и включить
в новом профиле вручную. Зашифрованная копия на том же Mac не является offsite.
См. [общий backup contract](../../secrets-management/docs/vault-offsite-backup.md).

Диагностические ответы не включать в backup/recovery или обычные screenshots.
Для воспроизводимой иконки из корня модуля: `swift tools/render-icons.swift assets`.
В `assets/` лежат PNG для Chrome и ICNS приложения; исходник рисунка — этот Swift
renderer. Иконка и справка не требуют Apple Developer account.

Удаление: закрыть Guard и защищённый Chrome, удалить `.app`, затем при необходимости
приватный каталог. Blocker удалить/выключить отдельно в Chrome. Это снимает
соответствующую клиентскую защиту; на роутере откатывать нечего.
Удалить также только manifest `org.ghostroute.guard.events.json` из пользовательского
Chrome NativeMessagingHosts; соседние manifests других приложений сохранять.
